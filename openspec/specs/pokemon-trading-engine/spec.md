# Capability: pokemon-trading-engine

## Purpose

Implements the Game Boy Link Cable SPI Slave engine, protocol synchronization, Pokémon data conversion, and trade state machine for Generation I and Generation II games.
## Requirements
### Requirement: Game Boy Link Cable Slave Handshake
The system SHALL act as an SPI Slave device responding to the master clock generated by a Game Boy console (~8 kHz clock rate) and complete the initial master-slave handshake protocol.

#### Scenario: Successful role negotiation
- **WHEN** the connected Game Boy sends master byte `0x01` (`PKMN_MASTER`) repeatedly
- **THEN** the system responds with slave byte `0x02` (`PKMN_SLAVE`) followed by synchronization blanks `0x00` until connection byte `0x60` or `0x61` is exchanged

#### Scenario: Auto-detection of Generation II console
- **WHEN** the connected Game Boy transmits connection byte `0x61` (`PKMN_CONNECTED_II`) during handshake
- **THEN** the system automatically identifies the session as Generation II (Gold, Silver, Crystal), sets the active generation to Gen II, allocates 441-byte trade blocks, and signals the web interface

#### Scenario: Safe interrupt execution without network blocking
- **WHEN** the link driver's GPIO interrupt service routine (`isrHandler`) processes incoming bytes
- **THEN** the interrupt service routine records status changes and generation triggers using non-blocking atomic flags without invoking heap memory allocations or network transmissions

### Requirement: Trade Center State Machine Synchronization
The system SHALL synchronize with the Game Boy's Cable Club Trade Center menu selection and transition through the full trade lifecycle (init, random seed exchange, trade block transfer, patch list exchange, selection, confirmation, and finalization).

#### Scenario: Entering trade center
- **WHEN** the Game Boy player selects the Trade Center menu item (`0xD4`)
- **THEN** the system acknowledges and prepares the trade block data for transmission

#### Scenario: Trade block transfer and patching
- **WHEN** the trade block is requested by the Game Boy
- **THEN** the system sends the formatted 415-byte party block preceded by 10 preamble bytes (`0xFD`) and 10 random bytes, followed by the calculated patch list with `0xFE` escape bytes patched to `0xFF`

### Requirement: Generation I and Generation II Trade Support
The system SHALL support data formats and protocol variations for both Generation I (Red, Blue, Yellow) and Generation II (Gold, Silver, Crystal) games, including Time Capsule trade restrictions.

#### Scenario: Gen I trading session
- **WHEN** the user selects Generation I in configuration or initiates a trade with a Gen I cartridge (`0x60`)
- **THEN** the system uses Gen I structures (415-byte blocks), action codes (`0x60` family), and a 151-species Pokédex table

#### Scenario: Gen II trading session
- **WHEN** the user selects Generation II in configuration or initiates a trade with a Gen II cartridge (`0x61`)
- **THEN** the system uses Gen II structures (441-byte blocks plus 389-byte Mail exchange), action codes (`0x70` family), and a 251-species Pokédex table including item and shininess attributes

### Requirement: Bi-directional Trade Data Handling
The system SHALL support both transmitting configured Pokémon to the Game Boy and capturing received Pokémon transmitted from the Game Boy into memory.

#### Scenario: Injecting configured Pokemon
- **WHEN** an outgoing trade is confirmed on both devices
- **THEN** the Game Boy receives the configured party data slot 1 from the system

#### Scenario: Receiving and storing traded Pokemon
- **WHEN** the Game Boy completes a trade with the system
- **THEN** the system captures the incoming Pokémon's party struct, original trainer details, moves, and nickname, making it available for inspection and modification

### Requirement: Non-Destructive Generation Switching
The system SHALL preserve user-configured Pokémon attributes (species, nickname, moves, OT details, and held items) when the trading engine switches active generation during auto-detection.

#### Scenario: Switching from Gen I default to Gen II on console handshake
- **WHEN** the Game Boy initiates a Gen II connection (`0x61`) after the user has configured an outgoing Pokémon
- **THEN** the trading engine switches to Gen II without resetting the configured Pokémon data to a blank default species

### Requirement: Hardware Status RGB LED on GPIO 48
The system SHALL control the onboard WS2812 addressable RGB LED on GPIO 48 to visually display the current trade engine state using colors matching the web dashboard.

#### Scenario: Displaying waiting state
- **WHEN** the trade engine is waiting for a Game Boy connection (`STATUS_WAITING_GB`)
- **THEN** the RGB LED illuminates in red

#### Scenario: Displaying connected state
- **WHEN** the link handshake completes with a Game Boy (`STATUS_LINK_CONNECTED`)
- **THEN** the RGB LED illuminates in yellow/orange

#### Scenario: Displaying in-room trade table state
- **WHEN** the trade engine enters the Cable Club trade room (`STATUS_IN_TRADE_ROOM`, `STATUS_SELECTING_POKEMON`, or `STATUS_CONFIRMING_DEAL`)
- **THEN** the RGB LED illuminates in blue

#### Scenario: Displaying trade completion state
- **WHEN** a trade successfully completes (`STATUS_TRADE_SUCCESS`)
- **THEN** the RGB LED illuminates in green

### Requirement: Gen II Link Data Patch Offset Alignment
The system SHALL align the patch list generator with the 2-byte Trainer ID offset used by Generation II Game Boy games to prevent memory corruption when escape bytes (`0xFE`) occur in party data.

#### Scenario: Patch list generation in Gen II
- **WHEN** `plist_create()` processes party data for a Gen II trading session
- **THEN** the offset calculation incorporates the 2-byte Trainer ID prefix so that patch list indices correspond accurately to `wLinkPlayerPatchedData` in Game Boy WRAM
